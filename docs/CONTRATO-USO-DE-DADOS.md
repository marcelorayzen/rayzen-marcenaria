# Contrato de uso de dados do projeto

**Estado:** contrato local de domínio; não há tela de consentimento, retenção executada, transferência de dados ou IA externa implementadas.  
**Versão:** 1.

## Decisão aprovada

Ao criar o acesso e iniciar o projeto, o cliente aceita de forma explícita e registrada:

1. armazenamento dos dados para operar seu projeto;
2. manutenção do projeto canônico para continuidade da operação e migração futura autorizada;
3. elegibilidade do projeto para uma evolução governada do produto e da IA.

A aceitação registra pessoa, projeto, data/hora, finalidades e versão da política. Ela não autoriza segredo, envio invisível, alteração automática do projeto ou liberação de fabricação.

## Como o banco pode melhorar a experiência

Dados aceitos podem entrar em uma fila de aprendizado governada: padrões, regras confirmadas, falhas, propostas corrigidas e decisões podem ser analisados para melhorar o produto. Antes de qualquer transferência a outro servidor ou provedor de IA, a implementação deve registrar a finalidade, conjunto mínimo de dados, destino, retenção, acesso e resultado. A reutilização não acontece automaticamente a cada salvamento.

O projeto canônico continua separado de qualquer dado derivado para aprendizado. Uma conclusão proposta pela IA deve manter sua fonte e passar pelos contratos de revisão e aprovação já definidos.

## Retirada e mudança de política

O contrato prevê retirada registrada para interromper novos usos de melhoria. A política operacional ainda precisa definir como tratar dados já processados, requisitos legais aplicáveis, prazo de retenção e pedidos de exclusão antes de entrada em uso real.
